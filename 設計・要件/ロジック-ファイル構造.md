# ロジック・ファイル構造

## 1. 実装方針

FlaskのApplication FactoryとBlueprintを使用し、画面処理・業務ロジック・DBモデルを分離する。段階ごとに機能を追加し、初期段階は開発用ユーザーで出品者を固定する。認証実装後はログイン中のユーザーを出品者として使用する。

実装順:

1. 作品作成・出品
2. 入札・落札
3. タグ検索
4. メールアドレスによるログイン認証
5. 作品/オークションのお気に入り

## 3. 機能別の処理

### 3.1 作品作成・出品

1. 描画画面でJavaScriptのCanvasを操作する。ペン種類はフロントエンドの設定一覧で管理し、Gペン・丸ペン・ぼかしなどを追加できる構成にする。
2. 保存時にCanvasをPNG化して送信する。バックエンドはPNG形式・サイズ・寸法を検証し、UUIDのファイル名で`static/uploads/artworks/`へ保存する。
3. `artworks`へ`draft`作品を作成する。初期段階は開発用ユーザーを`seller_id`として使用し、認証後はログインユーザーを使用する。
4. 作者はアカウント画面の下書き一覧から出品設定へ進む。タイトル・説明・タグ・開始価格・終了日時を設定すると、作品を`listed`へ更新して`auctions`を`active`で作成する。
5. `draft`は作者だけが閲覧・編集できる。`listed`以降は公開する。

### 3.2 入札・落札

1. 商品詳細画面内のフォームで入札額を受け付ける。別の入札画面へは遷移しない。
2. `auction_service`は`auctions`、入札者`users`、前最高入札者を`SELECT ... FOR UPDATE`でロックする。
3. オークションが`active`、終了前、自己入札でない、入札額が現在価格より大きい、残高が十分という条件を検証する。
4. 受理時は新しい`bids`行を追加し、入札者残高を入札額だけ減算して`wallet_transactions`へ`bid`履歴を追加する。前最高入札者がいる場合は、その入札額を返却して`refund`履歴を追加する。
5. 同一トランザクションで`auctions.current_price`を更新する。成功後は商品詳細画面を再表示する。
6. `flask close-auctions`をWindowsタスクスケジューラから定期実行し、終了済みオークションの落札者・落札入札・確定額を記録する。

### 3.3 タグ検索

1. `flask seed-tags`でタグマスタを登録する。
2. 出品設定では既存タグを複数選択し、`artwork_tags`へ関連を保存する。同じタグの重複付与は許可しない。
3. 検索で複数タグを指定した場合は、選択タグ数と一致するタグ関連を持つ作品だけを返す（AND検索）。

### 3.4 認証・権限

- 新規登録はユーザー名・メールアドレス・パスワードを必須とする。
- メールアドレスとパスワードでログインする。パスワードはWerkzeugでハッシュ化し、Flask-Loginでセッションを管理する。
- 描画、出品、入札、お気に入り、下書き閲覧はログイン必須とする。ゲストは公開作品の閲覧・タグ検索だけを行える。
- 状態を変更するすべてのPOSTフォームはFlask-WTFのCSRF対策を適用する。

### 3.5 お気に入り

- `bookmarks`はオークション、`artwork_bookmarks`は作品専用とする。
- 商品詳細画面のPOSTフォームで登録・解除する。各テーブルの一意制約により重複登録を防止する。
- アカウント画面では作品とオークションのお気に入りを分けて表示する。

## 4. DB・設定・テスト

- スキーマはFlask-Migrateで管理する。開発用ユーザーと初期タグはFlask CLIから登録する。
- `SECRET_KEY`、MariaDB接続URL、アップロード先、画像上限は`.env`で管理し、`.env.example`にはキー名と例だけを記載する。
- 自動テストは開発DBと分離した専用MariaDBで実行する。
- 最低限、PNG保存、下書きの権限制御、出品、入札/返却、落札確定、タグAND検索、メールアドレス認証、お気に入り登録/解除をテストする。
